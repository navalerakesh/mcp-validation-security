# Changelog

All notable changes to this project will be documented in this file.

The format is based on Keep a Changelog, and this project follows semantic versioning for published artifacts.

## Unreleased

### Added

- GitHub Action typed run/artifact outputs preserve the human-readable console default. Each invocation uses isolated artifacts; bounded local inspection checks subject digests and run/target/exit consistency without recomputing policy. Missing/corrupt output cannot turn collector exit zero into acceptance, and only the current invocation is uploaded.
- Explicit prompt scenarios reuse the bounded synthetic client-reply engine over modern HTTP/STDIO, with exact observed request maps, immutable private capture and no automatic model/consent/filesystem behavior.
- Optional signed two-boundary relay evidence validates operator-declared mappings, per-boundary protocol/capability identity, response/error translation, correlation, deadlines/attempt budgets, cleanup and existing controlled-state effects. The owned fixture includes wrong-route/target/correlation/response-ID, identity, replay, late/lost-response, caller cancellation and unavailable-observer controls. Baseline state is independently read; cancellation with an observed write is not rollback. No production relay or independent external observer is certified.
- Declared scale workloads cover 10/100/1,000 catalog schemas, 100/1,000/10,000 obligations, 1/2/4/8 owned STDIO runs and a bounded session-repetition soak. Measurements disclose their local workload and resource scope rather than asserting universal capacity.
- Explicit positive tool scenarios support finite operator-supplied modern client-input rounds over HTTP and STDIO, with exact request matching, request-local capabilities, opaque-state echo, schema validation and bounded private capture. No model inference, automatic consent or filesystem discovery is enabled.
- Existing tool `CustomScenarios` support one bounded positive argument object per exact tool name. Inputs are privately captured and schema-validated, missing/ambiguous/disabled requests retain debt, and response errors or incomplete client-input requests do not earn positive execution credit. Patterns, expected-error scenarios, custom performance scenarios and automatic client inputs remain unsupported.
- Comprehensive security baseline admission uses the existing signed identity matrix for actor binding, scope enforcement and actor/action/object authorization. `--identity-baseline` and independently reserved `--validation-id` inputs are checked before target setup; STDIO forwards them only from operator-owned environment configuration. Canonical selection supports signature-checked replay, while missing controls remain incomplete.
- Owned SDK-backed HTTP identity pilot exercises valid actor/scope credentials, caller-assertion and object-policy denials, a deliberately broken policy, observer unavailability and contradictory counter evidence. It verifies target/observer credential separation, bounded process output and timed cleanup; results qualify only the trusted owned fixture and evidence pipeline.
- Experimental import-only identity-policy matrices retain authorization, effective-actor, authentication, scope, role-binding and positive-control outcomes separately. Signed evidence pins an independently admitted matrix and run/target/route scope; malformed rows preserve explicit integrity gaps without hiding other known violations. Assurance-result `3.4.0` adds the optional canonical assessment. No identity collector, target execution or default activation is added.
- Assurance-result `3.3.0` adds optional, bounded request-failure counts by normalized HTTP method, status and failure kind. Historical missing attribution remains unavailable. Saved artifacts reject malformed attribution; canonical cloning preserves privacy and isolates valid entries. Transport counters are not protocol-failure verdicts.
- Experimental controlled-application state evidence contracts, evidence-only scenario reconciliation and bounded signed import with operator-selected observer trust. Write/no-op/failed-write, unavailable observation, audit, cleanup and replay distinctions are retained in a separate lane. No default activation or automatic target invocation is added. Assurance-result schema is `3.2.0`; rule catalog revision is `2026-11-11.1`.

### Fixed

- Canonical summary counters now include resource and prompt leaf outcomes, including authentication-required, skipped and inconclusive results; these can no longer disappear behind a tools-only summary pass rate.
- Resource reads and prompt retrievals require completed content evidence, not just HTTP success or metadata validity. Authentication-required, unavailable, input-required, cancellation and framework errors retain distinct non-success outcomes; generated-argument HTTP 400 no longer earns prompt execution credit. All resource content entries are checked, and private exception details are not emitted.
- Observed tool coverage requires a complete recovered catalog, one matching result per discovered tool and success evidence for configured invocation. Missing or inconsistent leaf evidence cannot inherit an aggregate pass; metadata-only Safe scope and known failures retain their distinct meanings. Extension-container lanes remain separate when validating planned scenario evidence.
- Outbound budgets reserve at dispatch rather than charging rejected or pre-cancelled requests. STDIO includes implicit initialization notifications, and shared HTTP request telemetry excludes preflight denials while preserving actual transport/response-limit failures. Atomic counters cannot overflow or grow after exhaustion. Zero-window STDIO reads do not consume partial response data before recovery.
- Scenario results must account for the pre-execution descriptor's identity, scope, layer and evidence lane. Ambiguous plans and duplicated or unrelated coverage cannot complete a planned obligation; missing evidence remains explicit after failure. Controlled-identity pack `1.2.0` retains scenario-level matrix coverage alongside its individual case evidence without core-conformance credit.
- Regression-only policy retains assessment-degradation enforcement when all new claims are outside the selected scope. Synthetic sampling rejects `tools` and `toolChoice` instead of accepting requests for an unadvertised capability.

Unselected extension findings and unscored official failures remain visible without becoming required comprehensive obligations. Dry-run audits retain the selected profile without inventing execution or assessment credit.

Selected but absent extension assessments create explicit debt. Informational load-probe scope advice remains visible without becoming a required operational objective. ### Security

### Fixed

- Canonical results no longer persist SDK runtime tool handles, and offline reporting tolerates older `1.x` artifacts that contain them.
- Draft 2020-12 tool schemas now accept unknown extension keywords such as GitHub MCP's `x-mcp-header` as annotations while continuing to validate known constraints.
- Client-profile compatibility coverage now remains in its own lane and cannot alter the neutral core score, evidence summary, or deterministic verdict.

- Remediation reports preserve finding-specific recommendations and classify missing active protocol evidence with protocol work instead of advertised-capability fixes.

- Official conformance import now fails closed on missing, unexpected, empty, or misclassified frozen scenarios and verifies the exact bounded `checks.json` bytes before parsing.
- Normative security violations now contribute to deterministic security assurance instead of remaining outside the security reducer.
- HTML reports now use assurance terminology, provide console-clean offline icons, meet WCAG AA text contrast, and retain bounded mobile table scrolling.
- Safe-mode reports now distinguish catalog validation from tool invocation, resource reads, and prompt execution; omitted tool annotations retain their MCP-defined defaults, and coverage exclusions remain provider-policy evidence rather than specification failures.
- GitHub Copilot Cloud Agent compatibility now treats missing explicit destructive hints as an advisory because MCP defaults omitted write-tool hints to destructive and GitHub does not document explicit hints as an admission requirement.
- AI-readiness enum and format advisories now derive schema intent from parameter names and titles instead of incidental words in free-form descriptions.
- Offline HTML rendering now displays the canonical persisted MCP schema version instead of a renderer-default profile.
- The local MCP wrapper now preserves numeric V2 exits for CLI outcomes and maps wrapper launch failures and timeouts to stable runtime exits.
- Canonical assurance threshold reasons now use culture-invariant percentage formatting so report snapshots remain byte-stable across operating systems and CI runners.
- Local and GitHub build gates now share one benchmark-catalog contract using the V2 `AssuranceReduction` workload name.
- NuGet and npm publication now run as independent protected lanes so one registry outage cannot suppress verification of the other; the GitHub release still waits for both.

### Changed

- Capability negotiation now records optional capability support discovered during protocol validation.
- Contributor workflow now includes tracked repository validation scripts and fixture-profile guidance.
- Release distribution guidance now documents the GHCR image alongside NuGet, npm, and standalone binaries.
- HTML reports now surface Run Status, Deterministic Verdict, and Trust Level as separate top-page decision cards.
- Public documentation now describes the current explicit-output artifact set, including audit manifests and the HTML decision surface.
- Safe mode is discovery/static analysis only; reports now expose skipped and unevaluated dimensions instead of treating missing evidence as success.
- Deterministic baseline/protocol/coverage verdicts are authoritative. Weighted score and L1-L5 trust remain descriptive and are capped by blocking security evidence, MUST failures, incomplete evidence, and authoritative reject verdicts.
- L5 human-readable wording is now `High Assurance` and explicitly does not represent formal certification or accreditation.
- Canonical validation and client-profile artifacts use schema version `1.1.0`, include validator provenance and final policy/verdict/coverage fields, and preserve same-major ingestion compatibility for older producer metadata.
- SARIF invocation status and properties, JUnit policy/error test cases and durations, Markdown/HTML evidence language, and profile summaries now project the same final canonical gate semantics.
- Composite Action validation evidence uploads run even when strict/balanced policy returns a nonzero exit.
- NuGet/npm packages, package SBOMs, checksums, release SBOM, signatures, and standalone archives are durable GitHub Release assets; GHCR mutable aliases use OCI version metadata for monotonic promotion.
- Release checksum subjects use portable bare filenames so signature backfill can verify every generated asset.
- Build validation fetches complete Git history before applying the sensitive-artifact publication gate.

### Security

- Release outputs now include stronger supply-chain trust signals across standalone binaries, packages, and container images.
- STDIO commands remain fully redacted in plans/artifacts while execution uses the reviewed in-memory command; process environments, output, framing, and shutdown remain bounded.
- Canonical clones remove raw HTTP/STDIO payload previews, headers, response bodies, exceptions, and target output; session logs no longer print response bodies and redact cookies, MCP session IDs, OAuth fields, known GitHub token forms, JWTs, and private keys.
- Authenticated automation supports environment `SecretRef` credentials so tokens do not enter process arguments or persisted configuration.
- Container builds pin the immutable .NET SDK `8.0.419` and runtime `8.0.25` image manifests, preventing moving-base drift from bypassing the exact SDK contract.
- Test dependencies no longer include unused Testcontainers/SSH.NET packages, and WireMock resolves a patched Scriban release.

### Migration Notes

- Pin `--mcpspec` and `--protocol-era` when reproducibility across protocol revisions is required. `latest` resolves to `2026-07-28`; legacy-only servers should select a supported legacy profile explicitly.
- Consumers parsing canonical JSON, client-profile summaries, SARIF, or JUnit should accept additive `1.1` fields and use deterministic verdict/policy fields for admission decisions. Do not gate on compliance score or trust label alone.
- CI workflows using the composite Action should keep `upload-artifacts: 'true'` so reports are retained on policy failure. Treat a nonzero validation exit as a completed evidence-producing policy decision, not automatically as transport failure.
- L5 remains enum-compatible as `L5_CertifiedSecure` in the 1.x API, but its human label is `High Assurance`; integrations must not present it as independent certification.
